# ADR-0002：OCR 走多接口降级链

|      |                                                                                               |
| ---- | --------------------------------------------------------------------------------------------- |
| 状态 | 已接受（2026-08-10）                                                                          |
| 影响 | 取代 [ADR-0001](0001-cloud-ocr-frontend-inference.md) 中「单接口 + 全局月度硬上限」的成本模型 |

## 背景

识别原先固定走 `GeneralBasicOCR`。该接口的免费额度用尽后即产生费用，需要一道自设的月度上限兜底，而这个上限设多少都是在「够用」和「花钱」之间取舍。

腾讯云的免费额度是**按接口分别计算**的，且不止一个接口能识别本项目的地图截图。

## 决策

把所有可用接口排成一条降级链，按识别准确率降序；某条被上游告知额度耗尽就自动降到下一条，全部耗尽才向用户报错。

**取消自设的月度硬上限**：账号已关闭后付费，额度耗尽时上游直接拒绝调用，超额扣费不可能发生。按用户/IP 的限流保留，防止单个用户刷光共享额度。

## 依据

对腾讯云 OCR 的全部接口逐一探测，再对有希望的做 82 张真实样张的端到端评测：

| 接口                      | 基底识别正确率 | 备注                     |
| ------------------------- | -------------- | ------------------------ |
| GeneralAccurateOCR        | 97.6%          |                          |
| GeneralFastOCR            | 97.6%          | 最快                     |
| RecognizeTableAccurateOCR | 97.6%          |                          |
| AdvertiseOCR              | 97.6%          |                          |
| RecognizeAgent            | 97.6%          |                          |
| GeneralBasicOCR           | 96.3%          | 原方案                   |
| GeneralHandwritingOCR     | 95.1%          | 只给多边形，需算外接矩形 |
| GeneralEfficientOCR       | 93.8%          | 有样张连层名都读不出     |

其余接口不可用：表格类把文字按单元格重组、坐标语义对不上；卡证票据类直接拒图或不返回可用坐标。

**「高」可信度档在全部 8 个接口上都是 100% 正确**——「不会自信地给错答案」这条性质不依赖具体接口。

## 后果

**得到**：免费容量随可用组合数成倍增加，且链首比原方案更准。

**付出**：多一层策略状态与响应归一化（各接口的返回结构差异很大）；每条策略每月会有一次「探路」调用撞到耗尽错误后才被标记；依赖面从 1 个接口扩大到 8 个。

**未决**：判定耗尽用的错误码取自官方文档，尚未在真实耗尽场景下验证。代码里有正则兜底与未识别错误码告警，详见[模块 01](../01-screenshot-recognition.md)。
