# ADR-0007：藏品/通宝增益的适配范围与"最佳情况"建模口径

| | |
|---|---|
| 状态 | 现行（2026-06-14 立） |
| 决策归属 | 维护者（与作者确认） |

## 背景

上游每次更新会引入大量藏品/通宝。用真实 `applyAnyRelics` 跑全 5 主题做覆盖扫描后，未被计算器算出的战斗相关藏品按效果类型分布很广：纯属性增益、条件型增伤/易伤、技力流、额外伤害、干员减伤/生存、经济/移动等。当前计算器是**静态期望公式**（非逐帧模拟），不同类型的可建模性差异很大，需要一条明确的"哪些做、怎么做、哪些暂缓"的口径，避免逐个临时决策、也避免把无法静态表达的效果强行塞进乘区产生静默错值。

判定哪些藏品需要独立黑板有两种情形（与既有代码一致）：

1. **通用黑板未捕获 key**：buff 的黑板键不在通用黑板读取范围（如 `damage_scale[tag]`、`sp_recovery_per_sec`、`enemy_take_element_damage_up`），通用黑板对它产不出值 → 独立黑板**补**上计算。
2. **效果与通用黑板算出不一致**：buff 带有通用黑板会读的键（如 `def`），但真实效果不同（如枯法 `defdown[support]` 实为**敌人**防御降低，通用黑板却会错加到干员身上）→ 独立黑板**改写**到正确乘区。

## 决策

### 1. 条件型增伤/易伤：按"最佳情况恒生效"建模

对"满足某条件后获得增伤/易伤"的藏品（闪避/抵挡后、敌人浮空/失重时、对被阻挡目标等），**视条件常驻**，把 `damage_scale` 倍率原样写入 `global_buff_stack.damage_scale_phy/mag`（与既有 `rogue_4_damage_scale[tag]`「文学」、`damage_scale[filter_tag]`「见厉」同口径）。本次据此适配：赏善郎(+100%)、万星园之辉(+30%)、枣面(+50%)、Blaze的电锯(+100%，距离未建模取最近最佳值)。

理由：计算器定位是「面板/理论 DPS 上限」，既有条件型黑板（锈刃-遗世独立、轰鸣之手满层等）一贯按最佳情况计；统一口径才能横向可比。

### 2. 限制触发次数 / 时间窗口型：暂缓

效果只触发固定次数、或仅在极短时间窗口内生效（如"技能后 1 秒内 +60%"、"部署后 10 秒内 +100% 且最多叠 15 次"）的藏品，**暂不适配**——按最佳情况恒生效会大幅高估稳态 DPS，按期望又缺触发频率模型。这类多数已在 `disallowedRelicNames` 黑名单中，维持现状。

### 3. 额外伤害类：暂缓至模拟引擎版本

藏品自身造成的独立伤害（额外子弹、技能时 AOE、部署落雷、每秒对阻挡目标法伤等，黑板键多为 `atk_scale`/`extra_aoe_damage`/`extra_magic_damage`）**暂不适配**。计算器当前没有「藏品独立伤害源」机制，无法决定其归入 auto/skill/cycle 哪一档、如何与干员 DPS 合并。等计算器演进为**模拟引擎驱动**版本（见 [ADR-0002](0002-expectation-formula-vs-frame-simulation.md)、[08-simulate-and-legacy](../08-simulate-and-legacy.md)）后再统一处理。

## 后果

- 正面：新藏品适配有明确分诊口径；条件型增伤横向口径一致、可比；暂缓项有据可查不反复纠结。
- 负面：
  - 条件型按最佳情况 = **理论上限**，对触发率低的藏品会高估，用户需理解"面板值"语义；
  - 额外伤害类在模拟引擎落地前一直缺席，部分藏品的真实收益无法体现；
  - "限次/窗口型"与"额外伤害型"的判定靠人工读藏品描述，无法从黑板数值自动区分（与 [ADR-0005](0005-manual-ingame-relic-name-lists.md) 同类）。

## 重启条件

- 第 2 条（限次/窗口型）：计算器引入触发频率/覆盖率模型后，可改为按期望计入；
- 第 3 条（额外伤害）：模拟引擎版本提供独立伤害源的时间轴归并后解除暂缓，届时逐个补 `atk_scale` 类黑板并按 [10-relic-buff-verification](../10-relic-buff-verification.md) 验证。
