# ADR 模板与写作约定

本目录存放无藏收录模块的架构决策记录（ADR）。每条 ADR 回答一个问题：**这个看起来"不对劲"的设计，是不是故意的；如果要推翻它，先决条件是什么。** 体例沿用[伤害计算器 ADR 模板](../../../Tool/DamageCalculator/docs/adr/template.md)。

## frontmatter 约定

```yaml
---
status: 补记 | 现行 | 已废弃
last-verified: YYYY-MM-DD
sources:
  - <决策落地处的源码相对路径，逐行列出；跨仓库文件以 arkrog_backend/ 前缀书写>
---
```

- `status: 补记`：决策早已发生但从未记录，由代码考古事后补写（首批 0001~0006 全部属于此类）。补记的"决策归属"统一写"原作者（未记录，由代码考古补记）"，背景与取舍理由属于反推，正文中如有推测须明示。
- `status: 现行`：决策做出时同步记录。
- `status: 已废弃`：被后续 ADR 推翻，正文顶部加横幅指向替代者，文件不删除。

## 正文四段（半页为度）

| 段落 | 回答的问题 |
|---|---|
| 背景 | 当时面临什么问题、有哪些备选 |
| 决策 | 选了什么，落地在哪些导出符号上（路径 + 符号名，**禁止行号**） |
| 后果 | 已经发生的影响，**负面后果必须写**，已知违例链接到 [known-issues](../known-issues.md) |
| 推翻条件 | 若要推翻本决策，必须先满足哪些可验证的前提（证据、对账、双轨对比） |

## 文件命名与编号

`NNNN-英文-kebab-case.md`，编号递增不复用；标题与正文中文。术语用词与[术语表](../../../../../docs/glossary.md)保持一致（无藏、记录、StagePreview、悬挂收藏等）。level 语义一律引用 `arkrog_backend/docs/Permission.md`。

> ⚠️ ADR 的首要读者是"想顺手修掉某个怪设计"的未来维护者。如果你正打算修改某条 ADR 涉及的代码，先读完该条的"推翻条件"再动手。
