# ADR-0003：自建本地 OCR，云端退为兜底

|      |                                                                              |
| ---- | ---------------------------------------------------------------------------- |
| 状态 | 灰度中（2026-08-16 起影子并行）                                              |
| 影响 | 取代 [ADR-0002](0002-multi-account-multi-action-ocr-chain.md) 的免费额度模型 |

## 背景

用户量增长超出预期。2026 年 8 月中旬的实测：日均 1000~1500 次识别，而降级链的全部免费容量是 16000 次/月，其中准确率最高的 4 条策略在 8 月 15 日前就已耗尽。

**这是结构性缺口而不是短期波动**：按当时用量推算月需求约 45000 次，是免费容量的近 3 倍。继续沿用「多买几个账号」的思路只是把同一堵墙往后挪。

## 决策

在自有服务器上部署开源 OCR（RapidOCR + PP-OCRv6_small，ONNXRuntime CPU 推理），最终排到策略链首，云端免费额度退为故障兜底。

产出与云端归一化后的形状完全一致（`{t,x,y,w,h}`），因此前端识别管线不需要为它做任何适配。

**先灰度影子并行**：本地服务与云端并发跑同一张图，云端仍是权威结果，本地结果只由前端用同一套管线再推一遍并上报结论差异。要用生产流量确认离线评测的结论，再切换主次。

## 依据

同一批 82 张真实样张、同一套识别管线（直接调 `inferFromItems`），与云端基线同口径：

| 指标        | 本地 PP-OCRv6_small | 云端基线    |
| ----------- | ------------------- | ----------- |
| 层数识别    | 82/82 = 100%        | 100%        |
| 基底 Top-1  | **80/82 = 97.6%**   | 79/82 96.3% |
| 基底 Top-2  | 82/82 = 100%        | 100%        |
| 高/中档正确 | 47/47 + 17/17       | 高档 100%   |

判错的 2 张都落在「低」可信度档且正确答案排第 2 —— **「不会自信地给出错误答案」这条核心性质在换引擎后依然成立**，这是敢于替换的前提。

部署机实测（2 vCPU）：单图中位数 1.6s、P90 1.7s，进程峰值 512MB，模型合计 30MB。

## 后果

**得到**：没有额度上限，账单为 0；准确率不降反升；云端 16000 次/月成为纯冗余。

**付出**：多一个需要运维的常驻服务与一台跨区机器的依赖；识别耗时从 0.6~1.6s 变成约 1.6s（本地推理比云端慢，但省掉了排队与降级探路）。

**未决**：灰度对照的生产数据尚未收集完；浏览器直连形态的鉴权（当前是后端服务端调用，用静态令牌）。
