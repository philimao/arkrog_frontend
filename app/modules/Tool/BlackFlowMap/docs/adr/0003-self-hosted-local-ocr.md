# ADR-0003：自建本地 OCR，云端退为兜底

|      |                                                                              |
| ---- | ---------------------------------------------------------------------------- |
| 状态 | 已接受（2026-08-16 影子灰度 → 2026-08-18 切为链首）                          |
| 影响 | 取代 [ADR-0002](0002-multi-account-multi-action-ocr-chain.md) 的免费额度模型 |

## 背景

用户量增长超出预期。2026 年 8 月中旬的实测：日均 1000~1500 次识别，而降级链的全部免费容量是 16000 次/月，其中准确率最高的 4 条策略在 8 月 15 日前就已耗尽。

**这是结构性缺口而不是短期波动**：按当时用量推算月需求约 45000 次，是免费容量的近 3 倍。继续沿用「多买几个账号」的思路只是把同一堵墙往后挪。

## 决策

在自有服务器上部署开源 OCR（RapidOCR + PP-OCRv6_small，ONNXRuntime CPU 推理），最终排到策略链首，云端免费额度退为故障兜底。

产出与云端归一化后的形状完全一致（`{t,x,y,w,h}`），因此前端识别管线不需要为它做任何适配。

**先灰度影子并行、再切主次**：本地与云端并发跑同一张图，云端为权威，前端用同一套管线把本地那份也推一遍并上报结论差异。灰度 2790 条后于 2026-08-18 切换。

本地**不作为 `OCR_STRATEGIES` 的一项**，而是链首的独立一步：它没有账号、没有按月额度、不该参与 dead 标记；更要紧的是往数组里插一项会让所有下标位移，而 Redis 游标存的正是下标。

## 依据

同一批 82 张真实样张、同一套识别管线（直接调 `inferFromItems`），与云端基线同口径：

| 指标        | 本地 PP-OCRv6_small | 云端基线    |
| ----------- | ------------------- | ----------- |
| 层数识别    | 82/82 = 100%        | 100%        |
| 基底 Top-1  | **80/82 = 97.6%**   | 79/82 96.3% |
| 基底 Top-2  | 82/82 = 100%        | 100%        |
| 高/中档正确 | 47/47 + 17/17       | 高档 100%   |

判错的 2 张都落在「低」可信度档且正确答案排第 2 —— **「不会自信地给出错误答案」这条核心性质在换引擎后依然成立**，这是敢于替换的前提。

部署机实测（2 vCPU）：单图中位数 1.6s、P90 1.7s，进程峰值 512MB，模型合计 30MB。

## 灰度实证（2790 条真实生产样本）

| 指标 | 结果 |
| --- | --- |
| 层数一致 | 99.7% |
| 基底一致 | 97.3% |
| 云端答案落在本地 Top-2 | 98.6% |
| 平均推理耗时 | 云端 717ms / 本地 1812ms |

**本地处于「高」可信度却与云端分歧：0 例。** 74 例分歧里 55 例双方都判「低」、12 例双方都没检出锚点；唯一一例云端「高」的分歧是本地那侧根本没检出锚点，而非自信地给了别的答案。本地偶尔更保守（14 例本地无解而云端有解，约 0.5%），是降级不是错误。

切换时云端已耗尽 7/16 条策略、游标落到 96.3% 档，即**本地当时已比云端实际提供的更准**。

## 后果

**得到**：没有额度上限，账单为 0；准确率不降反升；云端 16000 次/月成为纯冗余。

**付出**：多一个需要运维的常驻服务与一台跨区机器的依赖；识别耗时从 0.6~1.6s 变成约 1.6s（本地推理比云端慢，但省掉了排队与降级探路）。

**未决**：浏览器直连形态的鉴权（当前是后端服务端调用，用静态令牌，不能塞进 JS）；限流额度当初是为了防止刷光**共享的云端免费额度**，本地无额度只有 CPU，这条理由已弱化，待单独评估。

## 2026-10-30：迁到 ArkRog 同机

arkrog 扩容至 4GB 后，部署独立 `arkrog-ocr.service`，dev/prod 共用
`http://127.0.0.1:8977/ocr`，消除正常识别时的跨机图片传输。
复用 arkrec 的 RapidOCR 3.9.2、ONNXRuntime 1.28.0 和三个模型文件；
检测和识别是 PP-OCRv6 small，方向分类仍为 PP-OCRv4 mobile。
单进程、推理串行、2 线程，内存软阈值 750MiB、硬上限 900MiB。
超时、云端兜底和后端熔断保持原有行为，影子对照关闭。

同一批 20 张部署样图在两台机器返回的全部 631 个文字框（文字与坐标）完全一致。
arkrog 推理中位数 1648ms、最大 1808ms；arkrec 同批中位数 1754ms、最大 3698ms。
这次是迁移一致性验证，没有重新跑前述 82 张端到端准确率评测。
dev/prod 均通过实际后端 OCR 接口，并确认本机服务成功计数增加。
arkrec 旧服务保留供回滚；切回时需同时恢复旧地址和旧令牌。

服务源码、锁定依赖、systemd 和运维说明见后端仓库 `deploy/ocr/`。
